# commit: 변경사항 분석 후 컨벤션 커밋

현재 git 저장소의 변경사항을 분석하여 논리적 단위로 나누고, 컨벤션에 맞는 한국어 커밋 메시지를 작성해 **승인 절차 없이 바로 커밋**한다. 이 스킬이 호출된 것 자체가 커밋 실행에 대한 사용자 승인으로 간주한다.

## 워크플로우

### Step 0: 저장소 지침 확인

저장소 루트에 `AGENTS.md` 또는 `CLAUDE.md`가 있으면 읽어 커밋 메시지 포맷·컨벤션 지침이 있는지 확인한다. 있으면 이 스킬의 기본 컨벤션(아래 "커밋 타입" 참고)보다 **그 지침을 우선**한다. 없으면 이 스킬의 기본 컨벤션을 따른다.

### Step 1: 변경사항 분석

다음을 순서대로 실행해 현재 상태를 파악한다.

- `git status`로 스테이징 여부와 관계없이 존재하는 모든 변경(수정·추가·삭제·untracked)을 확인한다.
- `git diff`로 미스테이징 변경 내용을, `git diff --staged`로 이미 스테이징된 변경 내용을 확인한다.
- `git log --oneline -10`으로 최근 커밋 메시지 스타일을 참고한다(저장소에 커밋 이력이 없으면 생략).

변경사항이 전혀 없으면 그 사실을 알리고 종료한다.

### Step 2: 논리적 단위로 분류

전체 변경사항을 하나의 커밋으로 묶기 전에, 서로 다른 목적의 변경이 섞여 있는지 판단한다.

- 같은 기능·버그 수정에 속하는 파일들은 하나의 논리적 단위로 묶는다.
- 관련 없는 변경(예: 기능 추가와 무관한 설정 파일 수정, 별개의 버그 수정)이 섞여 있으면 **여러 커밋으로 분리할지 사용자에게 제안**한다. 단, 무리하게 쪼개지 않는다 — 하나의 작업 흐름 안에서 자연스럽게 딸려온 변경(예: 리팩터링에 따른 import 정리)은 같은 커밋에 포함해도 된다.
- 분리하기로 판단되면 사용자에게 묻지 않고 바로 `git add <file>`로 단위별 스테이징한 뒤, 단위마다 이 워크플로우의 Step 3~4를 반복해 여러 커밋으로 나눈다.

### Step 3: 커밋 메시지 작성

**형식**: `<type>: <한국어 요약>`

**커밋 타입**:

- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `refactor`: 동작 변경 없는 코드 구조 개선
- `chore`: 빌드 설정, 패키지, 잡무성 변경
- `docs`: 문서 변경
- `style`: 포맷팅 등 코드 의미에 영향 없는 변경
- `test`: 테스트 추가·수정

**작성 규칙**:

- 요약은 한국어로, 명령형 어미("~한다"가 아닌 "~ 추가", "~ 수정" 형태)로 간결하게 작성한다.
- 요약 한 줄로 부족하면 빈 줄 후 본문에 변경 이유(왜)를 중심으로 설명한다. 무엇을 바꿨는지는 diff로 보이므로 반복하지 않는다.
- 여러 논리적 단위가 섞여 분리할 수 없는 불가피한 경우, 가장 비중이 큰 타입을 기준으로 하고 본문에 나머지 변경을 요약한다.
- 커밋 메시지 마지막 줄에는 대화의 시스템 지침에 명시된 attribution 라인이 있으면 그대로 포함한다.

### Step 4: 바로 커밋

확인을 기다리지 않고 해당 파일을 스테이징한 뒤 heredoc으로 커밋 메시지를 전달해 즉시 커밋한다.

**단, 다음 경우에는 예외적으로 커밋을 멈추고 사용자에게 확인을 구한다** (되돌리기 어렵거나 의도치 않은 노출로 이어질 수 있는 경우로 한정한다):

- 스테이징 대상에 시크릿·자격증명으로 의심되는 파일(`.env`, `*.pem`, `credentials.json` 등)이나 그런 내용을 담은 파일이 포함된 경우
- diff 내용상 명백히 하드코딩된 API 키·토큰·비밀번호 문자열이 보이는 경우

그 외의 경우 승인 절차 없이 커밋까지 완료한다.

커밋 완료 후 `git status`로 결과를 확인하고 커밋 해시와 메시지를 간단히 보고한다. push는 사용자가 별도로 요청하지 않는 한 하지 않는다.

## 주의사항

- `git add -A`, `git add .` 대신 파일을 이름으로 지정해 스테이징한다.
- `--no-verify`, `--amend` 등은 사용자가 명시적으로 요청한 경우에만 사용한다.
